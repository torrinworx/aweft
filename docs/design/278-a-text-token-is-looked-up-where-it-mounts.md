# 278: A text token is looked up where it mounts

Amends design 181: the internal resolve step in `Typography` is filled, and it answers the
string a token resolves to.

## Decision

`text(source, values?)` on `@aweftjs/ui` answers a token: a component call `dom` mounts, which
also carries its source string and its values on a symbol, so code with no mount context can
still read what it was. `isText(value)` says whether a value is one.

**The render carries the language.** `context({ locale, catalog })`: `locale` is a BCP 47 tag,
`catalog` a plain object from key to translation. Both are optional, and both are on the
`Render` a page hands `mount`, `render` and `hydrate`. A render with neither shows every source
string as written. `localeOf(context)` answers the render's tag, for a component that formats a
date or a number with `Intl`.

**One resolve.** A token resolves to the catalog's own entry for its key, or its source when the
catalog has none; a key such as `constructor` never reads `Object.prototype`, and an entry that
is not a string is a loud assert naming the key. The key it looked up is recorded on the render,
so a static walk can say what a catalog lacks (`usedText(render)` answers them). Then the message is formatted with the token's
values and the render's locale. `textOf(context, value)` is that resolve as a string, for a plain
string (itself), a number, or a token; it takes the opaque mount context or the render `context()`
made, so a server module with a render of its own resolves a title with no mount anywhere. An
empty `locale` is no locale, and a tag `Intl` cannot read falls back to the host's own rules.

**Where the resolve runs.** Four places, and a page writes none of them:

- **A token child** is a component, so `dom` mounts it, and the component mounts the formatted
  message: text, and for a tag the value the tag's function answers. A value that is a cell is
  followed, so `{count, plural, …}` over a cell re-renders as the count moves.
- **A token in a prop** is claimed by `ui`'s `h` the way `theme` is (design 107): `splitProps`
  replaces it with a cell `dom` binds on the element, and `applyClaimed` writes the resolved
  string into the cell before the mount, following any cell among the values. The prop is then
  an attribute or a property carrying the translation, on the server's node after a hydration
  and on a fresh one after a mount. A hoisted `ui` template goes through the same split.
- **`Typography`** resolves a token `label` to its string before the modifiers run over it, which
  is the seam of design 181 filled: a modifier matches the translated word.
- **A head component** resolves a token child and a token attribute when it declares its tag, so
  a `<Title>` is translated and the tag the head list writes is text. The stage resolves an act
  module's `title` the same way before it announces it, so `ActInstance.title` takes a token.

A token mounted under a context with no `ui` systems, such as `dom`'s own `mount`, shows its
source formatted with its values rather than asserting, because a stray token is not a defect
that should take a page down.

**The message syntax** is a subset of ICU MessageFormat, parsed here with no dependency:

| written | means |
|---|---|
| `{name}` | the value under `name`; a cell is followed |
| `{n, plural, one {# item} other {# items}}` | the branch `Intl.PluralRules(locale)` picks for `n`; `=0`, `=1` and so on match the exact number first; `#` is `n` formatted for the locale; `other` is required |
| `{kind, select, book {a book} other {a thing}}` | the branch named by the value of `kind`, `other` when none matches; `other` is required |
| `<link>the docs</link>` | the value under `link`, a function from the inner content to what to mount, so a sentence with an element in it is one message; with no function under that name the inner content stands alone |
| `'{'`, `'}'`, `'<'`, `'#'`, `''` | that character; an apostrophe in front of anything else is an apostrophe |

Branches nest: a plural may hold a select and a tag may hold a hole. A message that does not
parse is an assert naming the offset and what was expected. Every parse is cached by source, so
a token written once and mounted a thousand times parses once.

**`ui`'s own strings go through `text()`**, written out in its components, and `text.json` beside
its `package.json` is the list of them, generated by `npm run text` and checked by the gate the
way `surface.txt` is. It is on the exports map as `@aweftjs/ui/text.json`, so an application's
catalog can carry the library's dozen strings beside its own. `auth` ships the same for its
sign-in form. Neither ships a translation.

`text` is the name of the theme family `Typography` renders on and the name of this export. A
theme entry and an export are different namespaces, and both are the plain word for what they
are.

## Why

The lookup has to happen where the context is, because the language is a property of a render
and not of a module: a server renders ten languages from one process. A token is the value that
carries a string to that place, and a component call is the shape `dom` already brackets, so a
hydration pairs it beside a static sibling. A bare mounter was measured first and rejected: it
renders to plain text with no brackets, and a hydration with `Hello ` and ` world` as bare
mounters beside a `<b>` pairs the wrong nodes and asserts, because the pairing walk reads the
brackets to know where a dynamic child sits.

`ui`'s `h` claiming a prop is what lets every component take a token in `label`, `placeholder`
or `title` without knowing it did: the value reaches `h` as any prop does, and a component that
passes it through to an element, which is what every one of them does, gets the string on the
node. The one component that reads the string itself is `Typography`, whose modifiers need it.

The syntax is ICU's because a translator and a translating agent already read it; it is a subset
because `Intl` has plural rules, number and date formatting, display names and text direction,
and the only thing the platform lacks is the message formatter, which is small. A formatter as a
dependency would be the first one in the stack, for a hundred and fifty lines.

Fixed per render rather than a cell every token follows: a change of language is a remount or a
navigation, and a live locale would be a subscription on every text node of the page, the cost
the performance pass on `core` and `dom` spent its effort removing.

## What this costs

A token is a function with a symbol on it, so a value that expects a string and does string
work on it (`label.length`, `'' + label`) gets the wrong thing; `textOf` is the answer, and the
places inside this package that read a label do it. A prop holding a token makes the element a
mounter, as a `theme` does.

Formatting follows the cells among a token's values through one subscription per cell, so a
message with three cell holes re-formats whole when any one moves.

`{n, plural}` reads `Intl.PluralRules`, which every browser and Node ship; a locale the host has
no rules for falls back to the host's own, which is what `Intl` does.

No fallback chain: `fr-CA` is one catalog, not `fr` with overrides, and an application that
wants the chain merges the two objects before it hands one over.

## Evidence

`packages/ui/tests/text.test.ts`: a token resolves to the catalog's entry and to its source with
none; a hole, a plural in a locale with `few` and `many`, an exact match, `#` formatted for the
locale, a select, a tag around a hole, a nested branch, each escape; a cell hole followed after a
write; a bad message refused with the offset and the fix in the message; a token in `placeholder`
written as the string on the element; a token in `aria-label` on a hoisted template instance; a
token child under `dom`'s `mount` showing its source; `Typography` resolving before its
modifiers so a modifier matches the translated word; a `<Title>` with a token child written as
the translation; `textOf` on a string, a number and a token; `localeOf`; every text prop `ui`'s
components take on `build`'s list. `packages/ui/tests/typography.test.ts` keeps design 181's
cases.

## What would reverse this

A live locale: a page that switches language without a remount and cannot afford the remount,
which would make the resolve a subscription. A second package needing the resolve, which would
move the token below `ui`.
